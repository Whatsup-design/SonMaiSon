Implement DM message search for the currently opened conversation only. Add a search icon in the DM conversation header. When the user clicks it, show a small search input. Use the active conversationId from the currently opened DM. Do not search across all DMs.

Use backend endpoint: GET /dm/conversations/:conversationId/messages/search?q=<keyword>&limit=20

Send header: Authorization: Bearer <accessToken>

Example request: GET /dm/conversations/49d22538-a03b-4ebc-a131-b8794defb2c2/messages/search?q=hello&limit=20

Search behavior: only search when the trimmed query has at least 1 character. Debounce input by around 300ms. Use encodeURIComponent(query) when building the URL. Show loading while searching. Show returned messages in a search results panel. If the query is cleared, clear results and loading state. If the user switches to another DM conversation, clear the search query and results. If backend returns empty data, show “No messages found”.

Expected response: response.data.data is an array of messages. Each message has id, conversationId, authorId, content, createdAt, editedAt, and author.

Do not replace the main message list with search results. If user clicks a search result, try to scroll to that message if it already exists in the loaded message list. If it is not loaded, show the result preview and optionally handle loading around that message later.

Important: always use the active conversation id. Do not call the endpoint without a valid conversation id. Do not search only from local frontend messages, because local state may contain only the latest messages. Show backend error message from error.response.data.message if request fails.
